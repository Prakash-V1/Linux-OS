# Practice Safety Notes

- Use a disposable Killercoda lab, not a production server.
- Read commands before running them, especially commands that delete files or change permissions.
- `>` overwrites a file; `>>` appends to it.
- Check a process ID before sending a signal. Stop only the test process you started.
- Do not format disks, repartition devices, or change mounts for these beginner exercises.
- Commands such as `systemctl`, `sudo`, `apt`, `rpm`, `ssh`, and internet tests depend on the lab and Linux distribution.
- Never commit passwords, private keys, access tokens, or real credentials to GitHub.
- Remove sensitive hostnames, IP addresses, personal data, and confidential log output before sharing.
- Verify each exercise before publishing it. Do not claim that you completed a lab unless you did.
- For privacy, choose a private GitHub repository and confirm its visibility settings.
